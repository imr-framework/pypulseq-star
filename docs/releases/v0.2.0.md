# PyPulseq-Star v0.2.0

**Release date:** planned August 2026  
**Release type:** Alpha / SoftwareX submission release

PyPulseq-Star v0.2.0 is the first publication-oriented release of the protocol-centered architecture. It connects familiar PyPulseq-style sequence construction with symbolic protocol references, explicit hierarchy and loops, immutable resolution, local plotting, concrete Pulseq export, and hierarchical gammaSTAR export.

## Highlights

- Protocol parameters remain traceable through symbolic expressions.
- `Sequence.resolve()` creates an immutable numeric realization for validation and Pulseq export.
- Compact loop-native sequence hierarchy is shared across plotting and writers.
- Logical read/phase/slice axes support axial, coronal, and sagittal mappings.
- ADC trains represent multiple acquisition windows with train-level timing semantics.
- FID, spoiled GRE, EPI, and TSE reference demos follow a common beginner workflow.
- gammaSTAR export preserves editable dependencies for supported protocol controls.
- Sequence-specific release scope distinguishes strict, flexible, and deferred tests.

## Reference sequences

### FID

Release-gated behaviors include:

- default export;
- averages loop;
- TE and TR changes;
- sample-count and dwell changes; and
- cross-representation RF/ADC agreement.

### GRE

GRE is included with flexible acceptance constraints. v0.2.0 supports:

- phase-encoding loops;
- FOV-dependent ky scaling;
- RF/ADC spoiling;
- TE/TR timing;
- orientation mapping; and
- Pulseq/gammaSTAR export.

Equivalent backend-specific block splitting, raster rounding, and graphical interpolation do not block the release when the logical sequence and timing invariants remain correct.

### EPI

Release-gated behaviors include:

- alternating readout polarity;
- discrete ADC windows;
- `n_y`-dependent train length;
- FOV-dependent phase blips;
- segmentation; and
- orientation mapping.

**Deferred:** fully interactive echo-spacing/readout-duration retiming after export is planned for v0.3.0.

### TSE

The v0.2.0 release gate requires a valid default TSE export with excitation, refocusing train, crushers, readouts, spoilers, and both output formats.

The demo also illustrates effective-TE metadata, phase-order controls, refocusing-flip edits, and orientation. These remain experimental demonstrations rather than strict v0.2.0 contracts.

**Deferred:** strict ETL mutation across local plotting, Pulseq lowering, and live gammaSTAR is planned for v0.3.0.

## Architecture changes since v0.1.0-alpha

- Replaced primarily literal protocol dictionaries with symbolic protocol references.
- Added an explicit expression and evaluation model.
- Added immutable numeric sequence realization.
- Standardized node/loop declarations and counter-driven variations.
- Expanded logical orientation support.
- Improved ADC-train and nested-loop lowering.
- Improved gammaSTAR protocol dependency export.
- Aligned the four demos with a common public workflow.

## Release-scope policy

See [`../release_scope_v0.2.0.md`](../release_scope_v0.2.0.md) for the complete test matrix and scope legend.

- Green/committed tests are strict release gates.
- Yellow/flexible GRE tests use invariant-based acceptance.
- Red/deferred tests are excluded from v0.2.0 and tracked for v0.3.0.

## Known limitations

- APIs may still change before v1.0.
- gammaSTAR live editing is limited to dependencies supported by the target runtime and exported contract.
- Arbitrary-gradient corner rendering can differ between center-sampled and edge-interpolated displays.
- Broad multi-vendor and multi-site scanner validation is not part of this release.
- Software timing checks do not establish scanner safety or clinical suitability.
- The framework is not a complete symbolic constraint or feasibility solver.

## Compatibility

- Python 3.10-3.13.
- PyPulseq 1.4 or later for `.seq` export.
- Optional Matplotlib dependencies for plotting.
- Optional dashboard dependencies for relationship inspection.

## Safety notice

PyPulseq-Star is research software. Every generated sequence must be independently reviewed, validated, and tested under appropriate institutional and scanner-safety procedures before MRI execution. This release makes no regulatory, clinical, or universal scanner-compatibility claim.
